# 路线图

## 第一阶段（已完成，2026-10-22 ～ 10-24）

目标：一条能在真实项目上跑通的本地前端交付流水线，命令行、网页控制台、桌面端三种用法都可用。

### 交付了什么

| 方面 | 内容 | PR |
| --- | --- | --- |
| 流水线 | 需求 → 设计稿 → Spec → 写代码 → 门禁 ⇄ 审阅修复 → 交付 / 熔断；放行只看门禁退出码，修复轮数硬上限；断点恢复（#9） | #1 |
| 桌面端 | Electron 应用，Windows 与 macOS（Apple 芯片）实测：启动、继承 shell 的 PATH、退出清理进程树、dmg 打包 | #2 #3 #5 |
| CI | 三平台跑 TS 测试、`verify.ts`、npm 包在仓库外可用的冒烟 | #4 |
| 编程 / 修复 agent | 用户自选：Claude Code、Codex、OpenCode、WorkBuddy、DeepSeek Harness；修复 agent 可与编程 agent 不同 | #6 |
| 控制台 | 工作空间式的桌面风格界面：按项目管理、按钮为主、流程时间线、按阶段分组的日志 | #7 |
| TypeScript 迁移 | 核心、控制台服务、Studio 图全部改为 TS，只依赖 Node；Python 版删除 | #8 #9 #10 #11 |
| 设置页 | agent 登录状态与一键登录、代理（含“用系统代理”和连通性检测）、API Key、熔断邮件 SMTP | #10 #12 |
| WorkBuddy 编程 | ACP 权限请求按 `toolCallId` 合并、拒绝时选 reject 而不中止整轮、只开放文件工具、关闭自动记忆 | #12 |

### 真实项目上的验证

演示项目 `wwk-demo-dashboard`（Vue 数据仪表盘）：

| agent | 角色 | 结果 |
| --- | --- | --- |
| Claude Code | 编程 | 从需求写出仪表盘页面，门禁通过交付 |
| Codex | 编程 | 修复窄屏横向溢出，交付 |
| DeepSeek Harness | 审阅 + 修复 | 审阅准确指出未使用的常量并修复，第二次门禁通过，36 秒交付 |
| WorkBuddy | 编程 | 标题栏刷新按钮 + 加载状态单测，改 4 个文件，门禁通过交付 |
| OpenCode | — | 未验证：本机它自己的模型 Key 无效，流水线按“agent 无输出”熔断 |

### 遗留

- OpenCode 未在真实项目上跑通（换一个可用的 Key 后重跑即可）。
- 熔断邮件只做过单测，没用真实 SMTP 发过。
- 安装包未签名、未公证；macOS 只打 arm64。
- Electron 视觉验收只在 Windows + Electron 45 上实测。
- WorkBuddy 不能执行命令（有意为之）；CodeBuddy 遇到任何被拒的权限请求都会结束整轮，所以预设只给文件工具。

## 第二阶段（候选，未排期）

按价值大致排序，开新会话时从这里挑：

1. **补齐验证**：OpenCode 跑一轮；真实 SMTP 发一封熔断邮件。
2. **发布**：macOS 签名与公证、x64 / universal 包，Windows 签名；GitHub Release 自动出包。
3. **多端实测**：UniApp、微信 / 支付宝小程序、Electron 项目各跑一轮完整流程（目前真实验证只覆盖 Web）。
4. **控制台体验**：运行记录的对比与重跑、门禁失败项直接跳到代码位置、多个项目并行运行。
5. **成本与可观测**：每轮 token / 耗时统计，按 agent 汇总。
