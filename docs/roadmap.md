# 路线图

## 第一阶段（已完成，2026-10-22 ～ 10-24）

目标：一条能在真实项目上跑通的本地前端交付流水线，命令行、网页控制台、桌面端三种用法都可用。

| 桌面端 | Electron 应用，Windows 与 macOS（Apple 芯片）实测：启动、继承 shell 的 PATH、退出清理进程树、dmg 打包 | #2 #3 #5 |

### 真实项目上的验证

演示项目 `wwk-demo-dashboard`（Vue 数据仪表盘）：

| agent | 角色 | 结果 |
| --- | --- | --- |
| Claude Code | 编程 | 从需求写出仪表盘页面，门禁通过交付 |
| Codex | 编程 | 修复窄屏横向溢出，交付 |
| DeepSeek Harness | 审阅 + 修复 | 审阅准确指出未使用的常量并修复，第二次门禁通过，36 秒交付 |
| WorkBuddy | 编程 | 标题栏刷新按钮 + 加载状态单测，改 4 个文件，门禁通过交付 |
| OpenCode | — | 未验证：本机它自己的模型 Key 无效，流水线按“agent 无输出”熔断 |

### 遗留

- OpenCode 未在真实项目上跑通（换一个可用的 Key 后重跑即可）。
- 熔断邮件只做过单测，没用真实 SMTP 发过。
- 安装包未签名、未公证；macOS 只打 arm64。
- Electron 视觉验收只在 Windows + Electron 45 上实测。
- WorkBuddy 不能执行命令（有意为之）；CodeBuddy 遇到任何被拒的权限请求都会结束整轮，所以预设只给文件工具。
- Codex（codex-acp 1.13.0）在工作区内的编辑和沙箱内的命令都不发权限请求：`agent` 和 `read-only` 两种模式都是 on-request + workspaceWrite 沙箱，`protected` 和 `allow_kinds` 在协议层拦不住它（实测改 `rules.yaml` 时 0 次 `session/request_permission`）。现在的做法：会话开始后切到 `read-only`（不让它的 auto_review 代批越出沙箱的动作），跑完把被改动的保护文件还原并在结果里列出（对所有 ACP agent 生效）。仍未覆盖：Codex 的 `allow_kinds` 不含 `execute` 时，沙箱内的命令照样会执行（无网络，写入限于工作区）。

## 第二阶段（2026-10-24）

目标：作业分支上全自动跑完「取材 → 需求 → 设计 → 复核 → 编码 → 门禁 → 验收」，人只在合并弹窗出现一次。施工单见 [phase2-work-order.md](phase2-work-order.md)。

### 交付了什么

| 方面 | 内容 |
| --- | --- |
| 工作流配置 | 包内默认 < `~/.web-workflow-kit/workflow.json` < 工作区覆盖；字段级来源、整体校验、脱敏快照、导出导入、文件夹搬家重新绑定 |
| 阶段注册表 | 主图按启用的阶段与 `order` 拼出；阶段间依赖与顺序校验；`stage_status` |
| 文档契约 | 01–06 = front-matter + 正文 + `machine` 块；零 token 校验（AC 覆盖、引用、占位符、回应表……）；素材按 hash 入库；版本历史 |
| 文档阶段 | 取材与需求、技术设计、文档复核（含仲裁）、产品验收；校验不过带问题清单重写；验收打回按 `return_stage` 重做 |

| 控制台 | 图片输入、开工问题清单与一键修复、合并弹窗、待处理横幅、系统通知、按配置画进度、指标弹窗 |

### 真实项目上的验证

在 `wwk-demo-dashboard` 的本地克隆上用真实 agent 跑三种输入（控制台服务、按页面的方式调接口），每次跑完自动预演并合并：

| 输入 | 需求 | 过程 | 结果 |
| --- | --- | --- | --- |
| 纯文字 | 页脚 | 技术设计被复核打回 1 次后重写；门禁一次通过；验收通过 | 合并为 1 个 squash 提交，01–03 入库 |
| 图片 + 文字 | 照图加可关闭的公告栏 | vision 经 codex ACP 30 秒写 01，图片入库；技术设计被打回 1 次；门禁 lint 失败，修复 1 轮通过 | 合并 |
| 设计稿（本地导出的 MasterGo JSON） | 顶部栏「刷新」按钮 | product 分析设计稿写 01；技术设计因占位符误报重写 1 次；门禁一次通过 | 合并 |

三次合并后演示项目的类型检查、lint、50 个测试、构建全部通过。角色：product / dev 为 Claude Code；tech 前两次为 Codex，第三次因 Codex 额度用完改为 Claude Code；修复为 Codex / WorkBuddy。复核打回的意见切中要害（如「测试放在 `src/__tests__/` 下，vitest 只收集 `tests/**/*.spec.ts`，测试不会运行」）。

跑的过程中发现并修复的问题：

- ACP agent 回 JSON-RPC 错误（Codex 额度用完）时，未处理的拒绝让整个进程退出；
- 进程中途退出后仓库可能停在作业分支上，新增「中断」检查与收尾；
- 占位符检查把 Vue 模板的 `{{ title }}` 当成没填；入库的 01 里记了本机绝对路径；落盘的运行记录显示的合并状态过期；手动跳过审阅被记成一次出错的调用。

未在这次验证里覆盖：

- DeepSeek Harness：本机 dsh 没有配置 DeepSeek Key（`MISSING_CREDENTIAL`），修复与审阅改用其他 agent；第一次运行因此熔断，流水线按「修复 agent 出错」正确停下；
- 直连 MasterGo 客户端读选中图层（本机没开 MasterGo），只验证了本地导出 JSON 这条路；
- 仲裁、验收打回重做只有桩测试，真实运行里没有触发；
- 桌面端只做了类型检查和 lint，没有重新打包实测图片选择对话框。

## 第三阶段（候选，未排期）

按价值大致排序，开新会话时从这里挑：

1. **补齐验证**：OpenCode 跑一轮；真实 SMTP 发一封熔断邮件。
2. **发布**：macOS 签名与公证、x64 / universal 包，Windows 签名；GitHub Release 自动出包。
3. **多端实测**：UniApp、微信 / 支付宝小程序、Electron 项目各跑一轮完整流程（目前真实验证只覆盖 Web）。
4. **控制台体验**：运行记录的对比、门禁失败项直接跳到代码位置、多个项目并行运行（失败 / 熔断运行的一键重跑已实现）。
5. **命令行接入作业分支**：`wwk run` 拉作业分支并在终端里给出合并选项；接上断点恢复的分支校验（`checkResume` 已实现）。
6. **时间与 token 预算**：`limits.time_budget_sec` / `token_budget` 目前只是配置项，尚未强制。
7. **MasterGo 物料导出**：现在只有 `get_selection_node` / `get_variables`，设计稿模式的 01 没有素材图。
8. **文档阶段丢弃 agent 的擅自改动**：codex 在 read-only 模式下改工作区文件也不申请权限；文档阶段（取材、技术设计、复核、验收）的 agent 若改了代码，现在会在提交时被白名单拦下、整次运行失败。更好的做法是这些阶段结束时把文档以外的改动存成 patch 后丢弃。
